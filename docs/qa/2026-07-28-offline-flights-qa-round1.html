  2. The drawer is grouped: Inventory, Airline, Outbound, Inbound, Supplier, Deadlines, Operations, Misc.
  3. Fill Supplier, Cost price, Cost currency, PNR, Contract/group, Ticketing deadline, Cabin class, Checked bag kg, Block status, Notes, Handled by.
  4. Close the drawer and reload the page.

Expect: every value is still there. Cost price is stored separately from the selling Price and never reaches the customer.

  1. Hit Columns in the toolbar. Tick Supplier and Cost price; untick Airline name.
  2. Reload the page.

Expect: your column choice survives the reload. ORG / TAKEN / AVAILABLE are fixed columns and always visible.

B3

Click any cell and edit it in place

Item 2 - editing from outside

  1. Click a Price cell - it becomes an input. Type a new value, press Enter.
  2. Click a Block status cell - it becomes a dropdown. Pick a value.
  3. Click a cell, change it, then press Esc.
  4. Reload.

Expect: the first two persisted; the Esc one did not. If a save ever fails you get a red toast and the cell snaps back to its old value rather than lying to you.

B4

Change one field across many flights at once

Item 2 - multi-edit

  1. Tick 2–3 rows. A bulk bar appears above the table.
  2. Set field → Block status → option → Apply. All selected rows change.
  3. Price → ± % → 10 → Apply price.
  4. Event → pick your test event → Link event. Then Unlink event.
  5. Select one row → Delete → confirm. Turn on Filters → Show deleted to see it, then Restore.

Expect: the percentage lands on whole dollars (no $412.4999). Selection clears after each bulk action. Deleted rows are hidden by default, never gone.

B5

Allocate seats per event, and watch it refuse bad numbers

Items 3 + 4 - allocation, ORG / TAKEN / AVAILABLE

  1. Find a flight linked to 2+ events with ORG around 20. Click the chevron on the left.
  2. Each event starts as global pool - no allocation, behaves exactly as before.
  3. Allocate 10 to the first event. The footer drops to Unallocated: 10 of 20.
  4. Now try to allocate 15 to the second event.
  5. Allocate 10 instead. Footer reaches Unallocated: 0 of 20.
  6. On an event that already has a live reservation on this flight, try allocating fewer seats than it has sold.
  7. Click the × to remove an allocation.

Expect: step 4 is refused - "only 10 of 20 remain unallocated". Step 6 is refused - "this event has already sold N". Step 7 returns that event to the global pool rather than blocking it. TAKEN is read straight from live reservations, so it can never drift out of sync.

B6

Item 5 - deadlines are actionable, not decoration

  2. Look at the flight ID in the list; hover the marker.
  3. Now set Block status to ticketed.

Expect: an amber dot beside the ID reading "Ticketing deadline in 1 day(s)", which disappears once the block is ticketed. Same treatment for an option that's about to expire.

B11

Lock a package to one flight

Item 7 - LOCKFLIGHT, backoffice half

  1. On your test event, flip Locked package on.
  2. Pick a flight from the dropdown - it lists only flights already linked to this event, and says how many seats each has allocated.
  3. Hit Lock. Now check the event's default depart / return dates.

M2

The allocation is a hard ceiling

Item 3 - seats per package

  1. In the backoffice, allocate 1 seat on that flight to that event.
  2. Search the flight step for 2 travellers.
  3. Search again for 1 traveller.

Expect: gone at 2, present at 1 - even though the flight still has plenty of unallocated seats. That's the hard cap you chose: an event cannot eat into another package's quota.

M3

Zero seats means zero

Item 3 - exhausted quota

  1. Set that event's allocation to 0.
  2. Search for 1 traveller.
  3. Remove the allocation entirely and search again.

Expect: invisible at 0 for any party size; back the moment the allocation is removed, because that returns the event to the global pool.

M4

A flight with a stopover stops saying "direct"

Item 5 - the stops column that was previously forbidden

  1. On an offline flight, set Out stopover to e.g. VIE, Out stop duration to PT2H, and stops to 1.
  2. Also set Checked bag kg and Cabin bag kg.
  3. Reload the flight step on the site and find that flight's card.

Expect: the card shows one stop with the layover, not "direct". Until now the database physically refused to store a connecting flight - the old constraint pinned stops to 0. Amadeus results are untouched.

M6

When the locked flight sells out, the package sells out

Item 7 - no silent re-pricing

  1. Keep the event locked, and set its allocation on that flight to 0.
  2. Reload the flight step.

Expect: a clean "החבילה אזלה" panel - and crucially, no Amadeus results appear instead. Falling back to a live search would quietly change the price the customer was promised, which is the whole reason to lock a package. Sold out means sold out.

The derived-consumed design, end to end
